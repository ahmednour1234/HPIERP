# API v2 — التخصصات، فلترة العملاء، منتجات المندوب

**Base URL:** `https://2026-test-new.hpi-eg.com/api/v2`
**Auth:** كل المسارات تحت `Authorization: Bearer <token>` (حارس `admin-api`).
**آخر تحديث:** 2026-09-06

---

## ⚠️ نقطة مهمة قبل أي حاجة: `specialist` مش `category_id`

في قاعدة البيانات **حقلين مختلفين تمامًا** على العميل، والخلط بينهم هو مصدر اللبس:

| الحقل | معناه | القيم | من فين تجيبها |
|---|---|---|---|
| `category_id` | **التخصص الطبي** | روماتيزم، جلدية، صدر أطفال، تخاطب… (20 تخصص) | `GET /specialties` |
| `specialist` | **نوع الجهة** | 1=صيدلية، 2=مركز طبي، 3=مستشفى، 4=طبيب | ثابتة في الكود |

**اللي إنت بتدوّر عليه (روماتيزم، جلدية…) هو `category_id`.**

مفيش جدول اسمه `specialists`. التخصصات مخزّنة في جدول `categories` ويميّزها العمود `type`:

- `type = 0` → **تخصصات طبية** (للعملاء)
- `type = 1` → **فئات منتجات** (للمنتجات)

### 🚨 تحذير على `specialist`

البيانات الحالية فيها فوضى: المفروض 1–4 بس، لكن فيه قيم زي `2147483647` (23 عميل) و`1500877740`. دخلت غالبًا من التطبيق كأرقام عشوائية.

**التوصية:** استخدم `category_id` للفلترة. لو محتاج `specialist`، ابعت 1–4 بس ولا تعتمد عليه في تقارير قبل تنضيف البيانات.

## 3. العملاء مع الفلاتر  ✨ جديد

```http
GET /api/v2/customers
```

بترجّع عملاء **المندوب المسجّل فقط**.

### الباراميترات

| الباراميتر | النوع | ملاحظات |
|---|---|---|
| `search` | string | يبحث في الاسم أو الموبايل أو اسم الصيدلية |
| `category_id` | int أو array | **التخصص الطبي** — من `/specialties` |
| `region_ids` | **array** | المنطقة، يقبل أكتر من واحدة |
| `limit` | int | الافتراضي 25 |
| `offset` | int | **رقم الصفحة** (يبدأ من 1)، مش إزاحة |

> ⚠️ `offset` اسمه مضلّل: هو **رقم الصفحة** مش عدد الصفوف المتخطّاة. `offset=2` مع `limit=25` بيجيب الصفحة التانية.

### أمثلة

```http
GET /api/v2/customers?category_id=46&limit=25
GET /api/v2/customers?region_ids[]=16&region_ids[]=17
GET /api/v2/customers?category_id=46&region_ids[]=16
GET /api/v2/customers?search=صيدلية&limit=50&offset=2
```

### مُتحقَّق منه فعليًا (المندوب 127)

| الفلتر | النتيجة |
|---|---|
| بدون فلتر | 473 |
| `category_id=46` | 184 |
| `region_ids[]=16` | 119 |
| الاتنين معًا | 41 |

الفلترين يعملان **AND** (تقاطع).

## 4. منتجات المندوب  ✅ موجود بالفعل

```http
GET /api/v2/stocks
```

بترجّع منتجات **فئات المندوب المسجّل فقط** — مش الكتالوج كله.

| الباراميتر | ملاحظات |
|---|---|
| `category_id` | فئة منتجات واحدة (من `/product-categories`). بدونها: كل فئات المندوب |
| `search` | كود المنتج أو الاسم |
| `type` | `4` = الرصيد الفعلي بالعربية. غير كده = الكتالوج المسموح |
| `limit` / `offset` | الترقيم |

### الفرق بين `type=4` وغيرها

- **بدون `type`** → المنتجات اللي **مسموح** للمندوب يبيعها (كتالوج فئاته)
- **`type=4`** → **الرصيد الفعلي** الموجود معه دلوقتي بالكميات

الأسعار بترجع **بسعر المندوب** لو متسجّل له سعر خاص، وإلا السعر الافتراضي.

### أمثلة

```http
GET /api/v2/stocks                      # كتالوج فئات المندوب
GET /api/v2/stocks?category_id=45       # فئة واحدة
GET /api/v2/stocks?type=4               # الرصيد الفعلي بالكميات
```

### مُتحقَّق منه (المندوب 127، فئاته 45،48،72)

| الطلب | النتيجة |
|---|---|
| `/stocks` | 6 منتجات |
| `/stocks?category_id=45` | 3 منتجات |

## 5. نتائج الزيارات  ✨ مُحدَّث

```http
GET /api/v2/visits/results
```

### أ) الرد بقى يحتوي المنطقة والتخصص

مش محتاج تجيب كل العملاء في request منفصل — البيانات جوه الرد:

```json
{
  "id": 18012,
  "customer_id": 1750,
  "note": "...",
  "latitude": "26.6982086",
  "longitude": "31.603488",
  "customer": {
    "id": 1750,
    "name": "دكتور جيهان محمد - المراغة",
    "mobile": "088436",
    "region_id": 51,
    "region":   { "id": 51, "name": "سوهاج - مركز المراغة" },
    "category_id": 46,
    "category": { "id": 46, "name": "اطفال عام" }
  },
  "img": "visit/2026-09-07-abc.png",
  "img_url": "https://2026-test-new.hpi-eg.com/storage/visit/2026-09-07-abc.png",
  "created_at": "2026-08-25T18:46:40+03:00"
}
```

### ب) فلترة من السيرفر

| Param | النوع | مثال |
|---|---|---|
| `from` | date | `2026-09-01` |
| `to` | date | `2026-09-30` |
| `region_id` | int أو array | `5` |
| `category_id` | int أو array | `46` |
| `customer_id` | int | `1750` |
| `limit` / `offset` | int | الترقيم (offset = رقم الصفحة) |

```http
GET /api/v2/visits/results?from=2026-09-01&to=2026-09-30&region_id=5&category_id=46
```

**مُتحقَّق منه (المندوب 124):**

| الفلتر | النتيجة |
|---|---|
| بدون فلتر | 3805 |
| `region_id=48` | 1607 |
| `category_id=46` | 1732 |
| `from=to=2025-10-29` | 15 |
| منطقة + تاريخ | 8 |

### ج) صورة الزيارة  ⚠️ كانت مفقودة تمامًا

الصورة **لم تكن تُحفظ أصلًا** — الجدول لم يكن به عمود لها، ولم تكن ضمن قواعد التحقق، فكانت تُهمَل بصمت عند الرفع. تم إصلاح السلسلة كاملة.

**الرفع:** `POST /api/v2/visits/results` بـ `multipart/form-data` وحقل `img` (صورة، حد أقصى 5MB).
**العرض:** `img` (المسار) و`img_url` (الرابط الكامل) في رد `GET`.

> الزيارات القديمة سترجع `null` في الحقلين لأنها سُجّلت قبل الإصلاح.

## 6. أسعار العميل في `/stocks`  ✨ جديد

```http
GET /api/v2/stocks?type=4&customer_id=1750
```

يوفّر نداء `POST /products/customer-prices` بعد اختيار كل عميل.

```json
"product": {
  "id": 14316,
  "name": "فوليك أسيد",
  "selling_price": 79,
  "customer_price": 75
}
```

- `customer_price` = سعر هذا العميل، أو `null` لو مفيش سعر خاص
- `selling_price` يفضل ظاهر للمقارنة
- بدون `customer_id` يرجع `customer_price: null` دائمًا

### بخصوص `selling_price = 0`

فحصت المنتجات الثمانية كلها في قاعدة البيانات: **كل الأسعار صحيحة ولا يوجد صفر واحد**، ولم أستطع إعادة إنتاج المشكلة.

لكن وجدت السبب المحتمل: لو `seller_prices` أو `customer_prices` بها سعر صفر لمنتج، كان **يدوس** على السعر الصحيح. أضفت حماية: أي سعر بديل بقيمة صفر أو فارغة **يُتجاهل** ويبقى السعر الأساسي.

**اختُبر:** بوضع `seller_price = 0` على منتج سعره 89 — رجع 89 وليس صفر.

لو المشكلة استمرت على الإنتاج، ابعت `product_id` والاستجابة الفعلية.

## 7. شؤون المندوب (HR)  ✨ جديد

البنود دي كانت في **لوحة الإدارة فقط** ومكانش المندوب يشوفها في التطبيق:
تقييم موظف · تطوير موظف · كورسات موظف · طلبات موظف · طلبات اجازة

كلها بترجّع **بيانات المندوب المسجّل فقط** — متحقَّق منه.

### القراءة

| Endpoint | الوصف |
|---|---|
| `GET /api/v2/hr/ratings` | التقييم الشهري: الدرجة + ملاحظة المدير |
| `GET /api/v2/hr/development` | ملاحظات تطوير المندوب |
| `GET /api/v2/hr/courses` | الكورسات المسندة له |
| `GET /api/v2/hr/requests` | طلبات الموظف |
| `GET /api/v2/hr/leaves` | طلبات الإجازة |

**فلاتر مشتركة** (لـ development / requests / leaves):

| Param | القيم |
|---|---|
| `status` | `0` قيد المراجعة · `1` مقبول · `2` مرفوض |
| `from` / `to` | نطاق تاريخي |
| `limit` / `offset` | الترقيم (offset = رقم الصفحة) |

`ratings` يقبل `month` كمان (مثال `2026-08`).

### التقديم من التطبيق

```http
POST /api/v2/hr/requests     # طلب موظف
POST /api/v2/hr/leaves       # طلب إجازة
```

```json
{ "note": "طلب إذن من الزيارات الصباحية", "date": "2026-09-20" }
```

- `note` **مطلوب** (حد أقصى 5000 حرف)
- `date` اختياري
- الطلب يُنشأ بحالة `0` (قيد المراجعة) ويبتّ فيه المدير من اللوحة

**Response 201:**
```json
{
  "id": 185,
  "note": "طلب إذن من الزيارات الصباحية",
  "type": 2,
  "status": 0,
  "status_text": "قيد المراجعة",
  "date": "2026-09-20",
  "created_at": "2026-09-07T14:40:52+03:00"
}
```

### شكل صف الطلب

```json
{
  "id": 160,
  "note": "طلب اذن من عمل الزيارات الصباحيه",
  "type": 1,
  "status": 0,
  "status_text": "قيد المراجعة",
  "date": null,
  "manager": "Moaz Ahmed",
  "created_at": "2026-06-07T14:43:38+03:00"

```

### مُتحقَّق منه (المندوب 124)

| Endpoint | النتيجة | من قاعدة البيانات |
|---|---|---|
| `ratings` | 18 | 18 ✅ |
| `requests` | 26 | 26 ✅ |
| `leaves` | 22 | 22 ✅ |
| `requests?status=0` | 26 | 26 ✅ |

**عزل البيانات:** المندوب 124 يرى 26 طلبًا والمندوب 127 يرى 8 — كل واحد بياناته فقط.

**التحقق:** `note` فارغ يُرفض بـ 422.

> ملاحظة: `courses` و`development` رجعوا صفر لأن الجداول فاضية في بيئة الاختبار، والمسارات نفسها شغالة (200).
