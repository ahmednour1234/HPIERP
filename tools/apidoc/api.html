Authentication

Passport bearer tokens, guard admin-api. Obtain one from POST /login, then send it on every protected call:

Authorization: Bearer <token>
Accept: application/json

Login authenticates against admins.mandob_code and only succeeds for records whose role is seller.

POST /api/v1/login
Content-Type: application/json

{ "code": "SELLER001", "password": "secret" }

200 OK
{
  "message": "You are logged in",
  "token":   "eyJ0eXAiOiJKV1Qi...",
  "admin":   { "id": 1, "f_name": "...", "storage": { ... } },
  "kilometer": 5
}

Failures: 403 validation errors · 422 {"message":"Password mismatch"} or wrong code · 401 missing/expired token on a protected route.

Conventions & gotchas

Destructive actions use GET. Every /delete endpoint is a GET taking ?id=. They are not idempotent-safe — never put them behind a link prefetcher or a browser accelerator.
8 endpoints require no token. Two are intentional (login, config). Three opt out explicitly with withoutMiddleware: product/export, product/barcode/generate, transaction/transfer/export. The remaining three — seller/rating, seller/indexdocument, seller/result/visitor/{id} — are declared after the auth:admin-api group closes in routes/api/v1/admin.php, so they are open. If that was not intended, move them inside the group.

Rate limit: 60 requests/minute per authenticated user (per IP when anonymous), applied to the whole api group.

Write endpoints accept application/json or multipart/form-data; the latter is required wherever a file or image is sent.
